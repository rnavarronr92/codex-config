# PostgreSQL review reference

Load this reference when the change includes SQL, Eloquent queries, migrations, schema, indexes, transactions or database concurrency.

Inspect:

- N+1 and unbounded queries.
- Missing pagination or chunking for large datasets.
- Nonselective filtering and sorting.
- Missing or unsuitable indexes.
- Transaction boundaries and isolation assumptions.
- Concurrent writes and lost updates.
- Uniqueness enforced only in application code.
- Expensive aggregates and repeated calculations.
- Migrations that could lock large tables.
- Destructive or incompatible schema changes.

For relevant queries:

1. Identify the SQL generated by the application.
2. Inspect relationships, schema and known indexes.
3. Estimate or obtain data cardinality.
4. Review `EXPLAIN` plans when safely available.
5. Compare alternative approaches.
6. Evaluate index selectivity and write overhead.
7. Recommend the simplest justified optimization.

Never recommend an index without explaining its expected benefit and maintenance cost. Never assume raw SQL is faster than Eloquent. Do not run `EXPLAIN ANALYZE` on data-changing statements or unbounded expensive queries.
